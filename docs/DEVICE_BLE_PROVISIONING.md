# FreshMate 日常固件 BLE 配网

BLE 是 LCD 配网之外的可选入口，默认关闭。固件使用乐鑫 protocomm BLE / Security 1；Wi-Fi 仍由 HomeStash 的既有网络管理器负责。独立诊断通过不等于日常固件验收通过，实际结果以末尾矩阵为准。

## 操作

1. 在 LCD“设置 → 蓝牙”主动开启配网，窗口有效 180 秒。
2. 读取 LCD 设备名和本次验证码；每次重开窗口都会变化。验证码只在本机显示，不放进普通日志或 Core 心跳。
3. Mac 客户端安装依赖到独立 Python 环境：`python -m pip install -r scripts/hardware/requirements-ble.txt`。
4. HomeStash 本机私有 `data/hardware/device.env` 中配置目标 Wi-Fi、Core 地址、设备 ID 和设备 Token；不要使用 SmartBadge 的私有配置。
5. 运行 `python scripts/hardware/provision-freshmate.py`，按提示输入设备名和验证码，客户端通过官方 Security 1 加密会话发送配置。
6. 只有 Wi-Fi 获得 IP 且网络保存成功后，才保存 Core 字段。成功后约 12 秒关闭蓝牙；失败可重试或使用 LCD。保存 Core 不等同于验证 Core 可达与认证成功，应另核对首页同步和心跳。

当前无手机专用配网页面；此端点不是通用乐鑫 Wi-Fi 示例的标准配置消息，不能把官方手机配网应用直接当作现成前台。

## 边界

- 录音、待处理媒体、OTA、受控休眠和启动自检期间不允许开启配网；配网窗口内禁止开始这些动作。
- 单帧 JSON 明文最多 480 字节，超出时客户端明确拒绝，当前用 LCD 完成长配置。
- 配置带 UUID 请求 ID；相同 ID 相同内容不会重复应用，相同 ID 不同内容拒绝。窗口内最多接受 8 个新请求，旧请求不能覆盖后续配置。
- 网络失败或取消恢复已保存网络，不提交新的 Core 配置。Wi-Fi 已保存但 Core 写入失败时返回 partial，不伪装全部成功。
- Device Token 是设备认证凭据，不是用户模型 API Key；AI Key 只留在 Core。
- 本机 UART 自动验收可用 `monitor.py --ble-private-file ...` 与客户端 `--private-file ... --verify`，临时文件权限必须 600；不得公开一次性验证码或原始私密文件。

## 内存与复用

0.4.0 和 0.4.1 BLE 启动失败，失败证据保留。0.4.2 起将 LVGL 的 64KiB 静态池通过官方 `LV_ATTRIBUTE_LARGE_RAM_ARRAY` 放入 PSRAM，并启用 SDK 外部 BSS；需核对 ELF 实际地址以及真机无线、LCD、音频、相机和休眠恢复。

共享 ESP-IDF 与 SmartBadge 不改动。蓝牙控制器及 protobuf-c 依赖在 HomeStash 私有缓存内准备，归档提交及 SHA256 锁定；Python Security 1 原样保留来源和许可证。

## 验收矩阵

2026-10-21 日常固件 0.4.3，使用现有 Korvo 和 Mac 客户端：

| 场景 | 结果 |
|---|---|
| 通用构建、ELF内存池位置、无本机密钥 | 通过；64KiB位于 `0x50000000` 外部BSS |
| 默认关闭、主动开启 | 通过 |
| 错误PoP拒绝后重新连接 | 通过；0.4.2容量1时失败，0.4.3恢复已验证的ACL4/LE3容量后通过 |
| 非法Core字段 | 拒绝 |
| 不可用网络失败后提交正确网络 | 通过 |
| 官方Security 1加密下发Wi-Fi和Core | 通过 |
| 相同请求重放及不同内容冲突 | 通过；冲突拒绝 |
| 联网保存后约12秒自动关闭 | 通过 |
| UART复位后NVS配置与首页恢复 | 通过；有一次初始Core连接超时，自动重连约47秒后恢复 |
| SC101IOT相机回归 | 0.4.3成功采集640×480、21,784字节JPEG并真实上传；0.4.2一次传感器ID无响应，保留间歇性问题 |
| 真实录音/播报 | 通过；用户确认“家里有什么”播报正常，串口核对271,404字节音频下载、播放成功及outbox清空 |
| 空闲180秒超时、再次开启更换PoP | 通过；实测180.410秒关闭，设备名及PoP均更换 |
| Light/Deep Sleep回归 | 通过；受控定时唤醒、首页及网络恢复，不代表自动节电策略或续航测量 |
| 手机配网入口 | 未实现；当前只有Mac客户端 |

0.4.2完成60秒12次只读采样，无意外重启，库存和事件未改变。BLE关闭后空闲内部RAM约118KB；BLE运行约65KB。此短测不等于长期压力或功耗测量。

0.4.2因Core连接超时，使用UART只写运行应用槽；事先保存启动选择区，NVS、分区表与原始备份保留。0.4.2→0.4.3真实OTA成功，新槽 `ota_1` 并确认 `valid`。0.4.3通用应用2,929,008字节，SHA256 `ebde6b99f1f38b39f99273cf71bd4011a291858dad114292fdf08bcf2012cd49`。

本轮相机成功发生在用户补充镜头盖未取下之后，但盖子当时是否已取下未独立确认；读取ID失败与遮光之间没有确定因果证据。

0.4.3另外完成240秒、48次只读采样，无意外重启、库存及事件不变。结构化结果见 [本轮证据](hardware-evidence/freshmate-ble-product-20261021.json)。
