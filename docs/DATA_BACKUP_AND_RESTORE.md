# 本地家庭数据备份与恢复

## 下载备份

进入“设置 → 数据备份与恢复”，点“下载家庭数据备份”。下载的是带格式版本、导出时间和SHA-256校验和的JSON文件，不需要AI或开发板联网。

包含：家庭名称与成员、存放位置、所有库存批次、完整库存事件（包括纠正）、购物清单及入库快照、照片/小票/条码候选与处理记录、本地商品记忆、菜谱、人数、烹饪进度、业务请求去重回执和恢复后的旧请求拦截记录。

不包含：`.env`、AI服务设置和密钥、后台登录配置、设备绑定与凭据、设备实时状态、模拟屏幕、固件发布信息与镜像、照片/录音/播报原文件、此前自动快照。迁移到另一台Core时，需要在新机器另行配置AI和设备。

备份仍包含家庭库存、原输入文字和识别证据等业务数据，文件未加密。校验和只能检测损坏，不证明来源可信；只恢复自己保存的文件。不要把真实备份提交Git。

## 校验与覆盖恢复

1. 先停止设备录音、拍照和做饭操作，关闭其他客户端的编辑页面。
2. 选择备份JSON，点“校验并预览”。网页当前支持20MB以内的文件。
3. 核对备份时间、库存/事件/购物/待确认数量，以及当前机器的数据数量。
4. 输入“覆盖恢复”，点“保存恢复前快照并恢复”。这是覆盖恢复，不合并两份库存。
5. 等待成功提示。设备身份、AI设置等机器配置不变，库存和业务进度回到备份状态。

预览后如果业务数据变化，服务器拒绝覆盖，需重新校验。恢复串行进入Core业务提交队列，SQLite中一次性替换业务数据；失败会回滚。成功响应丢失时，同恢复请求可以重试，不会再生成一份快照或重复覆盖。

恢复时会改变数据代次：新网页在轮询后清空旧库存编辑与购物核对草稿及旧请求重试标识；其旧代次提交会被拒绝，恢复期间排队的旧任务也会被拒绝。恢复前已执行、但不属于导入备份的请求ID继续被拦截，避免旧录音重传再次入库。这些拦截记录会随下一份家庭备份保留。

旧设备协议与没有代次头的调用保持兼容，无法识别其从未提交过的离线意图来自哪个数据时间点，所以恢复前仍需停止实际录音和操作。设备的SD待上传音频、缓存和本机配置不被恢复处理；当前未做设备文件系统的整机恢复。

## 自动快照与回退

每次覆盖之前，先把当前家庭业务数据写成快照。默认目录为数据库同级`backups/`，默认项目数据库对应`data/backups/`；可用`BACKUP_DIRECTORY`指定本机路径。新建目录权限0700、文件0600；先写临时文件并同步，再重命名与同步目录。快照失败，或恢复前快照超过网页20MB范围时，不覆盖数据库。

成功后可点“下载本次恢复前快照”，也可展开“查看自动保存的恢复前快照”。要撤回一次恢复，下载对应快照，再按相同流程选择、校验并恢复它；这次回退同样会先保存一份当前数据快照。

目前快照不自动清理、不做定时备份或云同步。需要另行保管下载文件，磁盘损坏时同一磁盘上的快照无法充当异地备份。当前数据库若已有不符合支持格式的损坏数据，会阻止覆盖，需保留数据库后另行离线修复；网页不是SQLite损坏修复工具。

## 文件与接口

格式标识`homestash-household`，版本1。按稳定键序计算业务载荷的SHA-256。导入校验支持版本、字段、唯一标识、位置引用、事件链连续性与当前快照、候选索引、购物/烹饪批次引用、允许恢复的业务状态；不导入系统设置。

- `GET /api/backups/export`：下载家庭JSON。
- `POST /api/backups/validate`：校验并返回摘要及当前业务数据指纹。
- `POST /api/backups/restore`：提交`requestId`、`backup`、`currentFingerprint`和`confirmation: "覆盖恢复"`。
- `GET /api/backups/snapshots`：恢复前快照列表。
- `GET /api/backups/snapshots/:id`：下载对应快照。

接口沿用后台登录与同源限制，不提供设备端访问。新网页写操作携带`X-HomeStash-Data-Epoch`；`/api/state`返回`dataEpoch`。业务恢复回执、数据代次和机器配置留在当前数据库，普通备份不导出机器设置。没有改历史migration；复用现有JSON状态和库存表。Next代理请求上限调整至22MB，Core对校验/恢复分别限制20/21MB。

## 验收

新增4组集成测试，全量软件测试共50项：

- 库存、事件纠正、购物入库、候选和烹饪进度完整往返；机器AI/设备/固件配置不导出、不覆盖。
- 快照可下载并再次恢复；跨重启恢复请求重放和购物来源防重复。
- 损坏校验和、未知版本、系统状态注入、事件链/引用不完整、过时预览和错误确认被拒绝；恢复中途写失败整笔回滚。
- 旧请求跨重启拦截、恢复时排队任务拦截、旧网页代次拒绝；登录/同源保护和跨库待确认图片恢复。

浏览器实测使用临时SQLite：下载2批备份；增加到3批；预览并恢复为2批；下载自动3批快照；再上传该快照恢复为3批；核对两次自动快照。未写入日常库存、未操作开发板，也未调用真实AI。证据见`product-evidence/data-backup-20261021.json`。
