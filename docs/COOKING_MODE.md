# 语音烹饪模式

2026-10-19。使用现有 FreshMate Korvo 固件的录音、上传、LCD 与播报接口，本轮功能在 HomeStash Core 和 Web 实现，无需新增硬件或重刷固件。

## 使用

运行 `pnpm dev`，打开 http://127.0.0.1:3000/app 。开发板每句话按 SET 开始录音，再按 SET 停止，等本次播报结束再录下一句。

1. “今晚四个人吃什么”：从真实库存匹配本地食谱，记录本次人数。
2. “开始做番茄炒蛋”：按上一次推荐人数开始；也可以明确说人数。LCD 和播报包含菜名、当前步骤与总步数，Web 同步会话进度。
3. “下一步”“上一步”“再说一遍”：切换或重复当前步骤，不扣减库存。
4. “放多少”“这个要炒多久”“没有这个材料怎么办”：基于当前食谱回答。没有单步计时数据时明确告知，不能把整道菜时间冒充当前步骤时间。
5. “做完了”：生成待确认的食材消耗计划，仍不扣减库存。
6. “确认扣减”：确认食谱用量，核验具体批次后事务扣减。“好的”等模糊回复不会被当作扣减确认。
7. “不扣减”：结束做饭，保留库存。实际用量与食谱不同时应走此路径，再在库存中记录实际消耗。

Web“今晚吃什么”页面提供对应按钮、待确认数量和批次。Web 动作不会自动触发真实开发板扬声器；目前真实 LCD 和播报通过设备自己的语音请求更新。Web 的独立设备模拟器继续独立运行。

## 状态与数据

- `active`：正在做饭，保存食谱快照、人数与步骤。
- `awaiting_confirmation`：做完了，保存待扣减批次、数量、单位和版本。
- `completed`：已确认扣减或选择不扣减。重复确认不会再次消耗。

状态保存在现有 SQLite `app_state` 的 `cooking` 项，无需新表或修改历史 migration。旧会话没有状态字段时按 `active` 兼容读取。

消耗只选择食品、未过期、同名且同单位的批次，优先较早到期、较早建立的批次；数量不足或单位不匹配时拒绝整笔扣减，不自行换算单位。确认后不静默更换已展示的批次。批次版本变化后要求重新说“做完了”检查，不能沿用旧确认。所有库存事件、会话完成和请求回执在同一事务中提交。

设备沿用录音 UUID 与内容摘要去重，服务重启或上传响应丢失后重传不会多跳一步或重复扣减。Web 提交 `requestId`，网络失败后同一动作保留原请求 ID；确认携带 `sessionId` 和 `revision`，防止旧页面确认另一做饭任务或已经更新的清单。解析中的语音也绑定当时任务、步骤和会话版本，任务变化后返回可播报的重试提示。

## AI 边界

真实模式使用已配置的百炼 ASR、OpenAI-compatible 结构化解析和百炼 TTS。Provider 获得候选菜名、推荐人数和当前任务摘要，不获得 API Key、完整库存批次或数据库访问权。结构化意图经过 Zod 校验，再进入烹饪服务和 InventoryService。

默认 Mock 使用四个本地模板和规则问答；选择外部 Provider 后已支持真实 AI 菜谱生成和当前步骤问答，结果进入相同的库存核对、购物与烹饪流程。计时器、唤醒词、连续对话和自动识别熟度仍未实现。Mock Provider 支持列出的固定命令，不代表完整自然语言理解。

## 验证

- `pnpm test`：设备接口、持久化重放、步骤重复、人数承接、明确确认、过期/类别/单位过滤、批次变化拒绝与跨批次失败回滚。
- `pnpm exec tsx scripts/hardware/probe-cooking.ts`：真实百炼 ASR/意图/TTS 联调，使用合成语音和临时 SQLite，不修改日常库存。结果和音频写系统临时目录，会产生云模型调用量。这个探针不等同于物理麦克风及扬声器测试。
- 真机结果见 `hardware-evidence/cooking-20261019.json`，只记录实际观察到的链路。

当前设备协议未在录音开始时绑定烹饪任务。跨断电或长时间离线恢复的确认录音，不能据此证明它针对录制时的任务；恢复后应先重新核对当前任务。本轮验证不覆盖离线旧确认与新做饭任务交叉的情形，后续需补充录制上下文协议。
