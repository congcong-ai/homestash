# 采购清单与订单实收关联

## 使用方法

先建立采购清单，再在订单截图中勾选实际收到的商品。在候选的“同时记到采购清单”中明确选择目标，核对本次实收后确认。系统只创建这一次库存批次，同时记下清单已满足数量；没有选择时只入库，不自动猜测同名清单。

关联仅提供同名、同单位的未完成项，并区分手动/食谱来源。多个同名项由用户选择；西红柿与番茄按现有名称规范视为同名，不做品牌、规格或计量单位的语义推断。名称或单位修改后原关联选择会清空，需要重新核对。

例如计划2箱，订单先收到1箱：库存新增1箱，清单累计满足1箱，剩余1箱。下一次关联同一清单再收1箱，就同时完成采购项；不会再次执行独立的清单入库。如果实际收到3箱但计划只有2箱，3箱全部保存在库存，采购只记为满足2箱。

如果结束订单仍缺货，清单不会因此完成。以后另买剩余商品时，在清单标记买到，再进入购买确认，默认数量为剩余量；只录入本次新收到的物品。已有收货后名称和单位须一致，不做箱/盒/克自动换算。

## 一致性和历史

订单进度、库存批次、采购回执在同一个SQLite事务中提交。采购关联携带版本号，清单被修改、移除或被其他窗口完成时会拒绝整笔提交；失败不会出现库存已经增加但清单未更新。原请求重试保持幂等。

清单保存原始计划量和每次满足量，以及对应库存快照和可选订单/候选引用。收货后消耗库存不反向增加清单缺口；需要再次采购请新增计划。已关联的收货记录保留用于核对，不能直接移除。手动新增采购不会合并进已有收货的旧计划。

食谱复核保留已有收货的计划，先扣除其中尚未收齐的计划额度，再建立额外缺货项，不重复生成同一份补货。语音和设备采购页使用剩余量，并对已有订单收货项提示核对剩余；这不是实时物流或下单状态同步。

备份包含采购收货快照和引用，验证累计、单位、库存批次及订单候选归属；旧清单和旧备份无新字段时保留原行为。本轮没有改历史migration、固件或SmartBadge。
