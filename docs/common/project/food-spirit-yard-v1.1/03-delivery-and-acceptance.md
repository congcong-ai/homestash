# 实施顺序、验证与交付

## 分阶段实施，不在每阶段等批准

### 阶段 A：确认基线与最小设计

保存 git status、相关已有 diff、SDK/板型配置与运行命令的摘要，不包含密钥。按 02 实际追踪源码并更正任何过期路径。输出文件级改动计划、产品与旧后台隔离方式、设备协议与存储设计。把门传感器、摄像头、声纹/服务权限的真实缺口前置。

先补语音分段日志和可重复的测量入口，记录旧路径基线；后续所有“更快”都与同一输入、相近条件比较。没有真实 Provider 可用时先用本地测试服务验证契约，不能冒充延迟结论。

### 阶段 B：实现可运行主链

先完成食灵业务状态和持久化、有限意图/工具、配套 Web 及设备协议；测试替身经过同样业务工具，明确标 simulated。复用 Core 最小增量，新的相机/语音消息不能写旧库存。

实现 T5 产品状态与显示/触摸、固定提示资源、门事件驱动及接话窗口。实现真实相机适配或根据缺件保留准确的不可用分支，软件的预览/保存/重试/删除链完整可测。声纹验证立即安排，不等全部完工再查权限。

同时完成 `05-tts-investigation.md` 的可配置合成与测量要求，保持原默认配置兼容。先交付低延迟可信路径，再处理长句/流式扩展，不在首次确认动作前播报成功。

### 阶段 C：联调、稳定与冲刺

主链稳定后才加入实际声纹称呼、最近回忆的主机轻展示、第二种食灵与计时。对空输入、噪声、重试、退出、网络/存储失败、重启和能力缺失处理。旧后台做必要冒烟回归，不为旧库存扩新功能。

## 应执行的检查

先查看 scripts、依赖与当前测试基线，再使用匹配的命令。仓库现有命令包括：

```sh
pnpm test
pnpm lint
pnpm typecheck
pnpm build
pnpm hardware:targets
pnpm hardware:build:generic --board tuya-t5-ai
pnpm hardware:check:ports
```

固件跨板公共接口有变化时，再验证可用的 Korvo 构建/主机回归；工具链缺失须精确报告，不能删掉相关测试绕过。只做本次必要验证，不无意义反复跑已经通过且未受后续改动影响的全量检查。

根据风险写有意义的自动化回归：新产品意图不写库存、同 ID 重试不重复角色/回忆、相机许可有效期与取消、文件保存失败不会确认成功、临时文件清理、删除/回看一致、未知成员降级、TTS 配置和缓存隔离/取消/首音行为。用临时数据库、临时媒体目录和本地 HTTP fixture，不动真实数据。

实际 UI 检查包含：配套产品入口、家庭角色/名称修改、拍照邀请与缺相机提示、预览/重拍/放弃/保存、回忆回看/删除、静默和 TTS 配置；检查 480×320 设备模拟画布和 390/320 手机宽度，处理控制台错误与溢出。有可用浏览器工具时实际操作页面并保存可审阅证据；不要只看 health 返回。

## 主链验收矩阵

| 场景 | 期望 |
|---|---|
| 正常/慢开、连续开门、轻碰 | 区分真实事件，避免重复邀请，不加成长分 |
| 无回应、关门、静默、取消 | 有限监听；无回应安静退出；不误拍、不自激活 |
| 说买了草莓、给它改名 | 只生成/改角色；不改变旧库存表和事件 |
| 两名成员/未知人 | 共用小院；声纹若已接通则有真实身份依据，否则通用称呼 |
| 当前同意拍照、过期“好”、倒数取消 | 只有当前有效许可可拍，取消/过期后旧回调不能补拍 |
| 相机缺失、采集失败、门还在转动 | 明确不可用/等待，不用占位图宣称成功 |
| 预览/重拍/放弃 | 临时媒体正确清理，放弃不生成正式回忆 |
| 保存失败、同 ID 重试 | 成功回执晚于真实落盘；不重复卡片，不丢旧回忆 |
| 重启、回看与删除 | 数据持久；授权访问；原图与卡片状态一致 |
| 断网/恢复、声音重试 | 本地反馈可用；TTS 重试不重复执行业务；错误可恢复 |
| TTS 方案/音色/速度切换 | 实际 Provider 生效，缓存不串音色；未连接本地引擎不伪装可用 |
| 旧后台与旧数据库 | 原逻辑和数据保留；必要路由/健康检查正常，不被新产品意图修改 |

建议同一核心流程连续跑 5 次并保留结果。没有硬件时只能完成软件/仿真部分，不能把它记入真机验收列。

## 最终交付

1. 可运行源码与入口/启动方式，后台兼容边界及新功能范围。
2. 更新本目录实施记录与功能状态：已实现且软件通过、已实机验证、冲刺未接、后做、不做分别标明。
3. CLI 命令、运行环境、结果与已存在/新增失败的区别；页面证据；固件版本、板型、镜像位置与 SHA-256。
4. 语音调查/分段测量与配置说明；不同模式的首音/完整耗时及条件，没测到就写未测。
5. 相机硬件依赖/接线核对项、门传感器参数、声纹真实接入结果；下一步真机操作要足够具体。
6. 已知限制及演示脚本，明确实时与录像、模拟与真实、可运行软件与缺件的区别。

不要求本轮发布网站、部署生产、创建 PR 或改 GitHub 设置。不要以某一缺件为由把全部软件主线停在文档或 UI 空壳上；也不要声称硬件缺失的完整产品已交付。
