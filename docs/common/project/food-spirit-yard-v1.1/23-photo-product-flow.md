# 主屏拍照产品链路实施

2026-11-06。用户主动点击拍照或明确语音拍照即发起采集，不增加拍前确认。授权边界以本次最新指令为准；不扩展为模型识别、库存写入、监控或自动保存回忆。

## 已实施

- 主屏 page3 → action13 不再请求 recipes 静态提示；加入独立异步单帧任务。重复点击同一进行中拍照去重，停止取消代次；占用中的语音先取消并等待旧任务退出，再启动拍照，录音状态下结束当前采集并移除未提交临时录音。
- hs_uvc_photo.c 从已验证 UVC 流程抽出正式接口，使用 PSRAM 保存本次 JPEG，保留选中模式帧间隔规范化、准确帧队列注册/读取/归还/注销/关闭。不输出照片串口数据，支持重复拍摄与取消，不替换旧诊断文件或 SDK。
- /device/v1/yard/photos/:id/{begin,upload,failed,status} 使用现有设备鉴权且限制 T5 板型；独立于旧 images 库存端点。设备内只传本次取帧结果，不调用视觉模型。
- Core 通过随机内部凭据桥接到同一个串行小院写队列；拍摄 ID、设备 ID、期限绑定，取消及重拍拒绝旧上传，服务重启撤销进行中请求。临时照片先 flush 写盘再 rename、持久化元数据，source=device 仅由设备入口设置。
- Web 两秒刷新状态和临时预览，保留重拍、放弃、标题、确认保存及回忆列表删除；重拍生成新请求由设备空闲轮询消费。软件模拟工具仍明确标注，和设备来源隔离。
- 明确语音拍照通过响应 action=photo 触发端上相同任务；闲聊、含糊同意不构成新拍摄指令。此路径尚待真实 ASR 验证。
- 能力只按近期成功上传与设备反馈展示，启动时为待验证；状态轮询不无限延长旧成功时间，缺相机取帧失败明确失败。
