# 本地招呼改为六句轮换

2026-11-06。用户认为单字“嗯”过短，要求简短的一两句话，并且每次有变化。本次仅调整新激活时的本地招呼，连续对话不重复招呼；不把尚未校验的设备时钟用于早晚问候。

六句配置位于firmware/apps/food-spirit-yard/greetings.json：

- 我在呢，你说吧。
- 来啦，我听着呢。
- 小冰在呢，怎么啦？
- 找我呀？说来听听。
- 我在听，有什么事？
- 来啦，想聊点什么？

Momo预生成PCM分别约2027、1623、2107、1782、2427、1947ms，运行时直接从Flash播放，不调用大模型或TTS，不下载网络音频。保留上一版你好/谢谢/再见音频。字幕显示本次招呼，播完恢复原接话状态。

随机数由板端提供，用六句洗牌袋轮换：每组六次各用一次；两组交界也避免连续重复。静默、自动续轮和打断后恢复监听均不额外播放招呼。源码yard_greeting.h与生成器共同固定六句数量，生成时检查配置。

9项相关回归通过；新增主机C回归覆盖64组随机种子、每组100轮六次选择，检查组内不重复与跨组不连播同一句，临时产物不进入项目。校验六句文案与实际生成资产一致。修改的TS文件ESLint与git diff --check通过。真实T5交叉构建通过，保留当前共享工作树的Wi-Fi键盘/相机/HTTP/会话代码。

已完成覆盖区域备份、刷写并逐字节回读，随后通过产品UART接话动作验证六次实际播放与停止，测试期间没有上传录音。实机听感与语音打断仍需单独验收，不能以随机选择逻辑通过替代声学判断。


## 停止响应与资源预算

检查发现旧招呼在主循环同步播放，增长为一整句后会推迟停止事件处理。因此按键、触屏、UART的停止回调先置独立volatile取消信号；PCM每帧检查，PCM取消信号不等待普通输入队列；停止收尾事件仍按输入先后执行，队列满时先丢弃旧排队操作以保证停止入队，随后主循环执行原会话取消与硬件静音排空。这样保留停止后紧接着接话的顺序。收到停止后不再启动这次录音。主机测试覆盖首帧之后置取消，仅发送一帧就退出。

最终构建AP有效镜像2996740字节，可用3866624字节，余量869884字节。六段招呼共381230字节PCM，放只读Flash，不启动时整包复制到RAM。生成器拒绝超过3秒的招呼，避免今后改文案又变成长开场。


## 真实节拍问题与修正

第一轮实际产品动作连测六次，选择[5,3,2,4,1,0]无重复，未上传录音；招呼中途停止含静音排空435ms，停止后紧接着接话410ms。但固定音频实测耗时[1992,1786,2153,4643,3018,2042]ms，两个样本被拖长，不能用PCM理论时长当成真实播放耗时。

保留原结果与串口日志：/tmp/homestash-rehearsal/greetings-device-slow-result.json、greetings-device-slow-serial.log。固定PCM原循环每次送帧后固定睡眠20ms，会在送帧本身因背压等待时再叠加20ms。改为累计PCM时钟计算剩余等待，与动态WAV播放路径一致。新增主机回归模拟每次送帧已阻塞20ms，1秒PCM不可再变成2秒。修正版已完成真机六次复验，结果如下。
