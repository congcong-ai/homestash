# 小院后台布局修复

日期：2026-11-06。

用户截图中的桌面导航纵向铺满、内容偏向右侧，原因是旧后台 globals.css 的通用元素规则：main 预留 238px 侧栏（中屏 195px），nav 默认 flex-direction: column。小院此前仅覆盖部分样式，手机断点恰好覆盖了两项属性，导致上一轮手机验收未发现桌面问题。

本轮仅调整小院 CSS Module，以及给现有故事表单添加局部样式类：

- 显式重置小院主容器宽度、最大宽度和外边距，统一居中内容区域。
- 导航明确横向排列、不压缩文字，移动端保留可横向滚动的可达入口，触控高度至少 44px。
- 页头明确完整容器宽度；加载状态也清除旧侧栏占位。
- 故事规则表单桌面双列、手机单列，补字段组、复选框与操作间距；保留其他会话已增加的规则逻辑。
- 表单焦点提示沿用小院色系，不改全局旧页面样式。

验证：先 CLI 执行修改页面 ESLint、独立 `.next-ui-fix` 生产构建，均通过。随后 Chrome 只读访问用户现有 `http://127.0.0.1:3001/app/yard`，检查 1440、1024、768、480、390、320 六种宽度，全部主容器左边界为 0、宽度等于视口，导航为横向且高度小于 100px，页面无横向溢出，浏览器运行异常零。人工查看桌面和手机截图。结果及截图在 evidence/ui-layout-fix，临时脚本和日志在 /tmp/homestash-ui-fix。

未重启用户现有服务，未操作硬件、数据库或设备配置；浏览器未执行写入动作。独立构建缓存已清理，tsconfig 仅撤销本轮 Next 自动加入的缓存类型路径，其他现场改动保持不变。
