# 后台设备管理

2026-10-21。Web“冰箱贴 → 我的设备”维护同一家庭下的多台设备，不再让最后一台上报覆盖整个设备目录。当前仍为本机单家庭模式；不是多租户平台。

## 日常使用

- 登记设备名称、独立ID和固件提供的boardId，生成一次性显示的设备Token。填入对应设备的Core设置；Token不是AI API Key。
- 凭据关闭后不再读取原文。丢失或更换设备时重新签发，原凭据立即失效，再把新凭据填到设备。
- 停用后拒绝该设备后续认证；重启Core或仍保留旧.env也不会自动复活。需要恢复时显式重新签发。
- 每台设备分别显示在线状态、最后通信、固件、屏幕及能力。45秒无通信视为离线；旧固件未声明能力时明确显示未上报。
- 固件发布选择相应板型。后台按镜像内标记校验，按板型维护最新版本；设备不能靠直接请求文件地址下载另一板型的镜像。

注册ID不可随意改名后复用旧身份。设备“名称”是展示名称，boardId是硬件兼容标识；相同芯片或相似商品名不能替代这个标识。

## 数据与兼容

- 独立记录保存在现有SQLite app_state的managed-devices；只保存高熵随机Token的SHA256摘要，不保存可回读原文。列表和状态API不返回Token或摘要。
- 现有DEVICE_ID / DEVICE_TOKEN只首次导入旧Korvo身份；它们不再充当所有设备的共享身份，也不会在重启时覆盖已登记状态。
- 历史physical-device保留为最近通信兼容投影，供旧调试工具使用；新目录按ID隔离，音频回执、正在生成的TTS和缓存目录也按ID隔离。
- 同一设备相同采集ID继续安全重试；不同设备碰巧相同UUID也不会读取或复用彼此的播报缓存。旧版根目录播报缓存可重建，不修改原始库存回执。
- 不修改历史migration，不新增云账号或自动上传。现有后台登录和同源限制同样覆盖设备管理。

## 本机API

- GET /api/devices：不含凭据的设备目录。
- POST /api/devices：登记，返回device及仅一次出现的token。
- POST /api/devices/:id/revoke：停用，幂等。
- POST /api/devices/:id/rotate-token：签发新凭据并恢复登记，旧凭据失效。
- GET /api/firmware?boardId=...：读取该板型最新固件。
- POST /api/firmware：二进制上传；网页携带X-Firmware-Board核对所选板型。

设备端继续使用Bearer Token和X-Device-ID。心跳可选hardware描述，包括boardId、chip、capabilities；与登记板型不符时拒绝，不允许心跳偷偷改变登记身份。

尚未实现手机BLE前台、批量云端设备运维、远程强制刷机或多租户授权；目前不为原型板继续扩展这些能力。
