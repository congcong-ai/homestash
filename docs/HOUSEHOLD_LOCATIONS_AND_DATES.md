# 家庭位置与批次开封提醒

## 如何使用

在“设置 → 家庭存放位置”新增储物柜、抽屉等位置，或修改已有名称。添加、编辑、采购确认、图片/条码候选和库存移动的下拉框共用当前地点。重命名保留位置ID，原批次及历史引用继续关联；位置目前提供新增和重命名，没有删除入口。

名称最多32个字符，同名（忽略首尾空格、大小写和全半角差异）会被拒绝，位置最多100个。名称已被另一操作修改时要求刷新，不静默覆盖。请求ID与事务保证同一新增请求重放不会增加第二个位置。

可用文字语音“把牛奶移到客厅储物柜”。Mock要求明确的完整位置名；外部模型会得到当前有限的位置ID和名称列表，结构化结果仍由Domain校验，不允许模型直接修改位置或数据库。未进行本轮真实百炼调用或设备语音实测。

添加或编辑物品时设置“开封提醒规则”：

- 默认：食品开封后2天，其他类别不启用；没有开封日期时不触发。
- 自定义：这一批开封后0至3650天，0表示开封当天；非食品也可明确选择。
- 关闭：不使用开封日期计算提醒，包装到期和建议日期仍然有效。

用户可随时恢复默认。先计算所有有效日期，再取最早日期用于批次状态、临期筛选、首页与食谱可用库存。开封天数是提醒规则，不代表质量或安全保证。已有包装到期日期不会被更长的开封规则延后。批次修改沿用版本校验、事件和最近操作纠正，不影响其他批次。

## 数据与兼容

HomeStash的通用LocationService负责位置规则，SQLiteRepository只负责持久化；FreshMate和其他家庭物品共用。位置沿用现有locations表，开封规则以可选的 `openedReminderDays` 保存在现有库存/事件JSON中，没有修改历史migration或表结构。

缺少字段的旧数据保持原行为，不批量重写；`default`表示恢复默认，数字表示自定义，null表示关闭。备份包含位置、批次规则和事件，可跨重启恢复。恢复前后的请求和网页数据代次保护继续适用。

本轮完成时日期仍使用UTC；后续已增加[家庭时区与日界线统一](HOUSEHOLD_CALENDAR.md)。按商品类别推断保质期和自动更改已有包装日期未实现。
