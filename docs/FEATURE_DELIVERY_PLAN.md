# 大功能交付计划

本计划依据根目录00/01/02文档及用户后续调整，按完整用户流程排序。已实现与未验收分开记录；详见[整体进度](BUILD_STATUS.md)。

## 当前阶段：Local Mode 与 FreshMate 核心 PoC

| 大功能 | 状态 | 范围与剩余项 |
|---|---|---|
| 家庭库存管理 | 主流程已完成 | 七类物品、批次、位置、日期、临期、事件与误操作纠正；不提供医疗决策 |
| 自然语言与做饭 | 主流程已完成 | 文字/语音→结构化意图→Domain；库存问答、食谱、烹饪续做及明确确认用量 |
| 多入口录入 | 主流程已完成 | 手动、语音、照片/小票、条码、订单截图、候选确认和失败重试；模型准确率仍需实际样本核对 |
| 采购与实收闭环 | 本轮完成 | 清单→订单分批实收→独立库存批次→清单余量→另买后补齐；明确关联、事务和版本保护 |
| 本地数据与恢复 | 已完成 | SQLite、备份校验、覆盖预览、恢复前快照、回退和旧请求保护 |
| 多设备与换板基础 | 软件分层已完成 | 后台设备身份/凭据、状态隔离、板型固件路由和公共应用契约；第二块物理板未适配 |
| 真实 Korvo 交互 | 核心 PoC 已验收，有保留项 | 录音/播报、屏幕、按键、相机、配网、OTA及受控恢复；多天弱网、功耗和新固件实刷仍须按报告区分 |
| Core断线后的离线查询 | 下一项大功能 | 当前仅有离线提示，不是完整离线库存浏览；目标是保留明确时间的只读快照，禁止用旧数据直接执行库存修改 |

下一执行项是离线只读使用闭环：先明确登录/退出后的缓存边界，再完成缓存读取、过期提示、重连更新及端到端验收。它不等同于断外网时本地Core不可用：Core仍在线且使用Mock/本地模型时，本地功能本来就可以运行。

## 后续阶段的大功能

| 大功能 | 当前状态 | 进入条件 |
|---|---|---|
| 多成员/多家庭账号与权限 | 只有领域模型预留，未实现 | 作为独立共享功能阶段处理，不把当前单账号冒充多人权限 |
| 微信 Quick Mode 与官方云 | 尚未开始 | 原路线Phase 2；当前仍遵守不自行进入微信正式上线、云端家庭和官方AI运营的约定 |
| 第二个真实板型适配 | 尚未完成 | 用户准备新板及必要能力；复用同一应用/协议，不重新实现全部产品逻辑 |
| 定制硬件、E-Ink和续航 | 暂缓 | 后续硬件决策和实际样机验证；不购买另一块通用开发板，不自行设计Rev.A |

## 大功能完成前暂缓

位置归档、更多主题人格、布局微调、原型板手机BLE前台、Korvo长期功耗优化和复杂弱网专项不占用当前主功能开发顺序。跨截图订单号对账、价格/SKU对账及自动物流/退款同步也不并入本轮采购基础闭环。

每个大功能交付都需要可运行入口、失败/恢复路径、独立测试数据、适当的CLI与界面验收、README和进度更新。生产部署已有脚本改动须保留，先核对其上下文，不混入其他功能提交。
