# HomeStash 整体功能进度

更新：2026-10-22。需求基准为根目录 `00_MASTER_PROMPT_KORVO_V2.md`、`01_PRODUCT_ARCHITECTURE_KORVO_V2.md`、`02_BUILD_ROADMAP_KORVO_V2.md`，并遵守用户后续 HomeStash/FreshMate 命名、SmartBadge 只读和已授权 Phase 1 的约定。本文只记录进度，不替代这三份需求。

| 图片识别后确认入库 | Web 已实现 | 真实百炼合成小票联调、候选编辑、取消和临时库确认；真实相机已抓图和上传；实物识别准确性仍需逐场景核对 |

“已实现”不等同于所有设备场景已验收，也不代表模型输出必然正确。涉及真实库存的修改仍由 Domain Service 执行，LLM 不直接访问数据库。

## 接下来的执行顺序

2026-10-21用户演示后调整方向：Korvo是原型，不继续围绕它投入完整消费版配置、长期功耗和手机BLE前台；优先后台与换板复用。

1. 已完成本轮基础：后台多设备登记、凭据签发/撤销、独立状态和缓存、能力展示、按板型隔离固件发布与下载。
2. 已完成本轮分层：同一FreshMate应用、公共ESP-IDF服务和device_port契约；Korvo硬件实现独立，统一构建目标选择。0.5.0编译通过但未刷机，当前板卡保留此前0.4.3。
3. 已补齐采购核对入库和统一待确认中心；已完成库存批次/临期与最近操作纠正；本地数据备份恢复和采购到烹饪消耗及补货的完整软件流程验收也已完成；后续优先手机Web试用及实际反馈。设备管理基础不等于整个后台已完工。
4. 待精简板必要能力、尺寸和成本边界确定，再实现真实第二个适配器，复用相同应用和协议，仅做必要的硬件回归。当前不购买新板、不设计Rev.A。
5. 手机BLE前台暂缓；Korvo多天弱网与功耗实验降为后续专项，不阻塞后台。保留现有安全配网、OTA和断网恢复能力，新的量产硬件仍须验证供电、内存、音频及适用的OTA。

详见 [固件多板适配](FIRMWARE_PORTABILITY.md) 和 [后台设备管理](DEVICE_MANAGEMENT.md)。不自行进入微信Quick Mode、定制PCB、开模、最终E-Ink或消费级续航承诺。

### 后续受控中途断电复测

用户重新执行全部断电约3秒后接回UART。本次慢速传输在262,144 / 2,216,720字节中断，下载期间UART断开，Core随后重新收到启动后心跳；仍运行原ota_1 / 0.3.5 / valid，首页及联网恢复。此项取得了下载中途断电保留原应用的证据，取代此前“该阶段未覆盖”的结论；不代表覆盖Flash全部指令及启动元数据提交瞬间的故障时序。

收尾已完成：用户通过LCD恢复正常Core（3101）并确认安装，自动重启回首页。最终实测0.3.5 / ota_0 / valid；关闭3102临时代理后仍收到新心跳，确认直连正常Core恢复。库存仍为4项、4条事件。临时代理及串口监控已停止，私密命令队列已清空，无需继续拔电。
