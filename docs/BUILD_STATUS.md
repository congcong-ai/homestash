# HomeStash 整体功能进度

更新：2026-10-20。需求基准为根目录 `00_MASTER_PROMPT_KORVO_V2.md`、`01_PRODUCT_ARCHITECTURE_KORVO_V2.md`、`02_BUILD_ROADMAP_KORVO_V2.md`，并遵守用户后续 HomeStash/FreshMate 命名、SmartBadge 只读和已授权 Phase 1 的约定。本文只记录进度，不替代这三份需求。

当前优先把产品主流程做齐。先实现每条主流程的可用版本，再集中做长期稳定性、功耗和样式优化；不会以更多细节优化代替缺失功能。

| 烹饪模式 | 已实现 | Start/Next/Previous/Repeat/Ask/Finish；真机开始、下一步、重复播报已验收 |
| 烹饪问答 | 已实现 | 外部 Provider 使用真实模型；Mock 使用食谱规则；不声称已启动计时器 |

| 图片识别后确认入库 | Web 已实现 | 真实百炼合成小票联调、候选编辑、取消和临时库确认；真实相机已抓图和上传；实物识别准确性仍需逐场景核对 |
| 小票图片提取 | 基础入口已实现 | 共用图片候选确认流程，未实现价格/SKU/订单对账 |
| 条码查询与确认入库 | 已实现 | 校验位/前导零、本地商品记忆、可选外部Provider；浏览器临时库闭环通过，照片读码及实体扫码枪未验收 |
| 订单截图专用解析 | 后续增强 | 现可走图片候选确认，未做订单字段及对账 |

“已实现”不等同于所有设备场景已验收，也不代表模型输出必然正确。涉及真实库存的修改仍由 Domain Service 执行，LLM 不直接访问数据库。

1. 已完成：语音库存、AI菜谱/烹饪、Web图片候选确认、Korvo相机、六页LCD、手动配网与OTA主流程，以及核心PoC集中验收。

4. 随后安排真实使用观察与复杂弱网测试，记录恢复时延、失败和资源变化；不以短时观察推导长期可靠性。
