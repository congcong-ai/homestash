# HomeStash：开源、本地优先的家庭物品管理平台

**家的小事，不必全靠记性。**

HomeStash 是采用 **MIT 协议**的开源家庭库存管理工具，支持本地部署。第一个应用 **FreshMate 智能冰箱贴**，帮你记住买了什么、什么要先吃、今晚能做什么。没有硬件，也可以先用浏览器管理。

**项目官网：[homestash.bebackpacker.com](https://homestash.bebackpacker.com)**

**项目地址：[github.com/congcong-ai/homestash](https://github.com/congcong-ai/homestash)** · [MIT 许可证](LICENSE) · [参与开发](CONTRIBUTING.md)

## 能帮你做什么？

| 生活中的时刻             | HomeStash 的用处                                                     |
| ------------------------ | -------------------------------------------------------------------- |
| 买菜回家，不想一项项记账 | 用文字输入购买信息，解析后记录食材与数量；硬件语音链路见下方进度说明 |
| 打开冰箱，忘了什么该先吃 | 按日期和开封状态查看优先食用提醒，日期可以手动修正                   |
| 到饭点，还在想“吃什么”   | 按现有食材推荐菜谱，查看缺少的材料并跟着步骤做饭             |
| 逛超市前，怕重复买       | 查当前数量与存放位置，记录消耗、补货和操作历史                       |
| 家里要管的不只有食物     | 同一套模型管理宠物食品、日用品、护肤品、药品等七类物品               |

它适合想减少遗忘与食物浪费的家庭，也适合重视隐私、自托管和可修改源码的使用者。

## 数据留在自己家，源码也在你手里

- **本地保存**：库存、操作记录、设置、设备和做饭进度存入本机 SQLite；不向 HomeStash 官方云同步。
- **默认无外部 AI 请求**：默认 Mock 模式使用有限的中文规则解析，不需要模型密钥。
- **外部能力由你配置**：选择第三方 OpenAI-compatible 服务后，输入文字和意图结构会发送给该服务；启用云端语音后，录音音频与播报文本会发送给对应的语音服务。这些模式不属于“完全不上传”。可配置自托管的兼容模型。
- **密钥留在服务端**：模型密钥不写入浏览器、库存数据库或 ESP32 固件。配置文件和运行数据不应提交到仓库。
- **MIT 开源**：自有代码允许使用、修改、分发和商用，保留版权与许可声明即可；第三方依赖遵循各自许可证。

HomeStash 是需要用户自行部署的开源软件，不提供 SaaS 服务。官网只介绍项目；线上后台仅供项目内部测试，通过独立登录页进入，不对外提供家庭库存托管。自行部署后，数据保存在你自己的设备或服务器。

## 不止是智能冰箱贴

**HomeStash 是通用底座，FreshMate 是厨房场景应用。** 物品、数量、位置、开封日期、操作事件和设备协议可以复用；食谱和做饭流程属于厨房应用。

现有分类包括食品、药品、保健品、宠物食品、日用品、护肤品和其他物品。可以先用于家庭储物柜、宠物口粮、梳妆台或药箱的库存记录。全新的流程和设备交互仍需开发适配，并非已经提供对应的专用产品。

本地运行后访问 `/applications` 查看更多场景。**硬件选型、制作与接入说明后续补充**，不影响先从浏览器开始使用。

## 快速启动

需要 Node.js 22+、pnpm 9.15.9；macOS/Linux 需提供 `lsof`，Windows 可用 WSL。无需 Docker。

```sh
git clone https://github.com/congcong-ai/homestash.git
cd homestash
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

- 项目首页：[http://127.0.0.1:3000](http://127.0.0.1:3000)
- 本地厨房：[http://127.0.0.1:3000/app](http://127.0.0.1:3000/app)
- 更多应用：[http://127.0.0.1:3000/applications](http://127.0.0.1:3000/applications)

`pnpm dev` 会先清理 3000/3100 端口，再启动 Core；健康检查通过后启动 Web。设置设备 Token 时也会清理并监听设备端口 3101。Ctrl+C 结束两个服务，启动前请确认对应端口没有需要保留的服务。

默认 Mock 模式无需密钥。数据库首次启动自动建立在 `data/homestash.db`，重启保留记录，全新安装不自动填充演示数据。备份时先停 Core，再复制数据库；运行中不要只复制 db 而遗漏 WAL。

生产构建预览：

```sh
pnpm build
pnpm start
```

## 服务器部署

官网：**[https://homestash.bebackpacker.com](https://homestash.bebackpacker.com)**。参考 FDE 的原生部署方式：Node.js 22+、pnpm、专用低权限用户、PM2、Nginx 和 Let's Encrypt HTTPS，无需 Docker。沿用 SQLite，数据库保存在服务器共享目录。

```sh
cp .deploy.env.example .deploy.env
# 填写 SSH、TLS 邮箱；先审计服务器端口，再填写确认后的两个端口。
pnpm server:install --check
pnpm server:install   # 首次：仅安装运行环境、访问保护、Nginx、HTTPS 和开机自启
pnpm server:deploy    # 首次发布及后续每次更新均使用此命令
```

本次官网使用 Web 3022、Core 3023，仅绑定 `127.0.0.1`。首次安装可重复执行，已完成时直接跳过。日常部署在本机临时目录安装锁定依赖、lint、类型检查、测试和构建；服务器仅安装 Linux 生产依赖，不上传本机 node_modules 或 `.env`，不在服务器重新编译业务代码。锁文件未变化时复用上一健康版本的运行依赖。

官网首页和 `/applications` 公开，不需要登录。官网引导访问者获取源码、自行部署，不提供公共在线后台。项目内部测试使用独立 `/login` 页面登录，未登录访问 `/app` 会跳转该页面，库存 API 返回 401；不会出现浏览器认证弹窗。用户名及密码保存在服务器 `/var/www/homestash/shared/access.txt`，不展示在官网或预填表单。本地开发默认不启用登录。

生产配置为 `/var/www/homestash/shared/.env`，初始使用无需密钥的 Mock 模式。需要外部模型时编辑此文件，再执行日常部署使其生效；不将开发机的 AI 密钥自动复制到服务器。生产硬件接口默认关闭。

发布目录：`/var/www/homestash/releases/`；`current` 原子切换版本，健康检查失败会恢复旧版，成功后只保留当前版与上一个健康版。数据库 `shared/homestash.db` 独立于版本目录，代码回滚不回滚数据库。完整的端口审计、备份、管理密码与验收命令见[部署说明](docs/DEPLOYMENT.md)。

## 三分钟试用

1. 打开“我的厨房”，输入 `买了两个西红柿、一盒草莓和十个鸡蛋。`。
2. 在“家中库存”查看数量、位置与日期，试用开封、部分消耗、用完或补货。
3. 输入 `今晚两个人吃什么？`，查看本地食谱与缺少的食材。
4. 选择番茄炒蛋，点击“开始做饭”，逐步查看说明并问“放多少？”。

默认 Mock 只识别有限句式；自然语言能力取决于所选 Provider。网页“冰箱贴”中另有软件模拟器，其示例操作不代表硬件实测结果。

## 常见问答

### 有开源、能自己部署的智能冰箱贴软件吗？

有，HomeStash 的 FreshMate 是一个 MIT 开源的智能冰箱贴应用，提供本地家庭库存、日期提醒、基于库存的食谱建议和做饭步骤。可以先在电脑上运行网页，再考虑设备接入。硬件链路的实际状态见[进度记录](docs/PHASE_1_PROGRESS.md)，完整硬件指南后续补充。

### 有不把家庭库存传到官方云的工具吗？

HomeStash 将库存与操作记录保存在本机 SQLite，不向官方云同步。默认 Mock 不调用外部 AI；启用第三方模型或云端语音时，相关输入仍会发送给相应服务，因此需按所选配置判断数据是否出网。

### 不买硬件，能使用 HomeStash 吗？

可以。安装后通过浏览器使用库存、提醒、食谱与做饭流程，不需要先买智能冰箱贴。当前服务绑定本机，手机访问和公网部署需要另外配置网络与访问保护。

### HomeStash 和 FreshMate 有什么区别？

HomeStash 是通用的家庭物品管理平台；FreshMate 是它的首个应用，面向冰箱与厨房。底层支持七类物品，可复用到其他家庭库存场景。

### 可以接本地大模型吗？

可以配置自托管的 OpenAI-compatible 服务。在设置中选择对应 Provider，填写带 `/v1` 的服务根地址与模型名。是否离线运行取决于该服务及其依赖；默认 Mock 则不需要大模型。

### HomeStash 免费吗？允许商用吗？

HomeStash 自有代码按 MIT 协议开源，可免费使用、修改和商用，需保留版权与许可声明。外部模型、语音服务和硬件的费用另计，第三方依赖遵循各自许可证。

### 能自动识别照片、自动下单补货或多人同步吗？

已接入图片识别和条码查询后的人工确认入库；自动采购、多人账号和云同步未实现。模拟器的 Camera 事件不改变库存。库存消耗与补货由用户操作确认，不根据做饭步骤自动扣减。

### 临期提醒可以保证食品安全吗？能指导用药吗？

不能。日期和新鲜度仅供提醒，请以包装、储存条件与实际状态为准。药品只管理库存，不提供诊断、剂量或服药建议。

## 配置 AI

在 `.env` 填写 `AI_API_KEY`（本地模型可不填）后重启 Core。在应用设置中选择 OpenAI-compatible，填写服务根地址和模型名称。

`AI_PROVIDER`、`AI_BASE_URL`、`AI_MODEL` 只作为未保存设置时的默认值；界面保存的设置优先。更换服务请在界面更新。错误响应、超时或非法结构化输出不会改变库存，也不会静默回退成 Mock 假装成功。

## 语音陪做饭

现有 Korvo 可说“开始做番茄炒蛋”“下一步”“上一步”“再说一遍”“放多少”。说“做完了”后先核对用量，再明确说“确认扣减”或“不扣减”。库存不足、单位不匹配或批次变化时不会自动扣减；Web 可查看步骤和确认计划。[操作与验证说明](docs/COOKING_MODE.md)。

## 整体主流程进度

按根目录三份原始需求推进的状态和顺序，统一查看 [整体功能进度](docs/BUILD_STATUS.md)。

新增问法：“家里有什么”“西红柿还有多少”“今天先吃什么”“牛奶开封了”“把牛奶移到冷冻室”“吃了两个番茄”“番茄扔掉了”。多批次同名物品需到库存页选择，不会猜测要修改哪一批。

“购物清单”支持手动记录、按菜谱缺口加入、标记已买到、核对实际购买信息并确认入库。“做番茄炒蛋缺什么”只查询，明确要求加入时才保存；标记买到不会自动增加库存。确认时可修改实际数量、类别、位置和日期，新建独立批次，重复提交或重启后重试不会重复入库。

“待确认”集中展示照片/小票、条码及已买到的购物项，并提供已处理记录和识别失败重试入口。原图不落库，图片识别失败后需重新选择原图。[使用流程与验收边界](docs/SHOPPING_AND_REVIEW.md)。

选择外部 AI 后，“今晚吃什么”支持真实生成菜谱；可输入人数和晚餐要求，生成结果会标记为 AI 菜谱。菜谱的已有/缺少食材由当前库存重新核算；烹饪问题通过已配置模型回答。Mock 仍使用有限模板和规则。Web 图片识别和候选确认已实现；Korvo Camera 已复测成功，设备六页导航已接入；连接设置和 OTA 的验收范围见下文。

## 拍照或小票确认入库

Web“拍照入库”支持选择图片、模型识别、编辑候选和勾选确认。识别时不写库存，确认后才创建物品与事件。数量不明需人工补齐，日期不凭空推断；重复确认不重复入库。视觉模型配置为 `AI_VISION_MODEL`，复用 Core 的服务地址和 Key。[操作及验收边界](docs/IMAGE_INTAKE.md)。

### Korvo 拍照

固件新增 MODE 拍照入口，SET 继续负责录音。拍照后到 Web“拍照入库”点击“刷新设备照片”，核对并确认后才写入库存。协议、恢复方式和真机验收范围见 [相机接入说明](docs/KORVO_CAMERA.md)。

LCD 六页导航和 Web 状态同步的操作与验收边界见 [设备页面说明](docs/KORVO_SCREEN.md)。

## 设备连接与固件更新

LCD 右上角“设置”提供网络扫描、手动连接、Core 地址和凭据设置，以及固件检查和确认升级。Web“冰箱贴”页可发布应用 `.bin`；设备确认后才安装。通用发布固件使用 `pnpm hardware:build:generic` 构建，不嵌入本机网络和设备凭据。首次迁移分区仍需 UART 和完整备份。[配置及 OTA 操作、恢复和验证边界](docs/DEVICE_SETUP_AND_OTA.md)。

## 条码入库

打开“我的厨房 → 条码入库”，输入包装数字或使用键盘式扫码枪；查询后核对名称、类别、数量、位置与日期，再明确确认入库。查不到时可以手动补全，确认过的商品会在本地记住名称和分类，不继承上一批的数量或日期。

默认只查询本地记录。显式设置 `PRODUCT_LOOKUP_PROVIDER=open-food-facts` 才会向外部商品库发送条码，不发送家庭库存或照片。照片读码取决于浏览器支持，手机实拍和实体扫码枪仍需专项验收。[使用、隐私和验证边界](docs/BARCODE_INTAKE.md)。

## 当前开发重点：后台与多板复用

2026-10-21演示后，优先完善后台产品体验和固件复用，不继续围绕Korvo原型投入手机BLE前台或长期功耗优化。已有配网和OTA保留。

后台“冰箱贴 → 我的设备”支持多设备登记、一次性凭据、停用/重新签发、独立状态和能力。固件按板型发布与下载，不能因芯片相同就互刷。[设备管理](docs/DEVICE_MANAGEMENT.md)。

固件使用一份FreshMate应用、公共ESP-IDF服务和编译时选择的板级适配器。`pnpm hardware:targets`列出目标，`pnpm hardware:build:generic --board korvo-s31`构建当前板型。0.5.0已编译但未刷入；第二块物理板尚未适配，现有实测基线仍为0.4.3。[复用边界与新板接入](docs/FIRMWARE_PORTABILITY.md)。
